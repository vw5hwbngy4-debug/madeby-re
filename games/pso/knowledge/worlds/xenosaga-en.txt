### RELEASE_NOTES.md
# Xenosaga I+II DS - Complete English Translation v1.0

## Final engineering changes

This release replaces the earlier Rough English v0.1 RC1 line with a runtime-tested v1.0 build.

Key fixes include:

- reconstructed chapter cards using the original indexed palette/map structure and safe LZ encoding
- preserved the known-good RC1 YES-training branch behavior
- cleaned the first-battle tutorial wrapping across the EVC corpus
- reflowed 910 mechanically safe one-word-tail dialogue blocks
- removed remaining player-facing Japanese from normal and deep EVC text layers
- translated item descriptions in `1/db/item.bin`
- changed the battle type glyphs to **P / E** using the actual battle spritebank
- preserved fixed event/text field spans where required to avoid branch regressions
- independently verified the final BPS by reapplying it to the clean Japanese ROM

## Residue classification

Structured player-facing scans at release time:
- normal EVC Japanese text: 0
- KJM/title Japanese text: 0
- player-facing deep EVC Japanese text: 0
- BDY Japanese text runs: 0
- item-description Japanese: 0

Thirteen Japanese 0x4D fields remain intentionally because they are internal/SFX-style cues such as impact/rumble sounds rather than translatable player-facing prose.

Three `param00/01/02.txt` files retain Japanese developer/config comments. They are not normal in-game player text.

## Runtime status

The final candidate was user-tested and reported to work excellently, including the opening YES tutorial path and first battle.

This is not a formal exhaustive every-state full-game certification.

### TECHNICAL_RECORD.md
# Technical Record

## EVC corpus

The project catalogued 29,461 translatable EVC records across 18,078 units. This includes 12,836 dialogue blocks and 5,242 standalone EVC text units, representing 13,126 unique source strings.

## Choice layer

459 choice menus were identified with 1,286 Japanese choice options. The supported translated choice layer has 0 remaining Japanese options.

## Absolute branch relocation

The key runtime failure in an earlier test build was not a translation-content problem. Variable-length English text changed EVC byte offsets, while absolute branch targets still referenced their old positions. The opening YES route therefore jumped to an invalid location and froze.

The relocation pass identified 1,322 branch opcodes and relocated 1,304 absolute targets, with 0 unresolved or invalid targets in the completed pass.

Opening YES target example:

- Original Japanese: `0x0D57`
- Vector beta reference: `0x0F2C`
- Broken earlier test build: `0x0D57`
- RC1 runtime fix: `0x0E3A`

## BPS verification

The browser implementation follows the BPS1 format, including source/target size parsing, metadata, SourceRead, TargetRead, SourceCopy, TargetCopy, signed relative offsets, and the three footer CRC32 checks. SHA-256 is used as an additional canonical source, patch and output gate.

The canonical patch was independently applied to the clean source with Floating IPS during package validation. The resulting SHA-256 matched the expected runtime-tested RC1 exactly.
